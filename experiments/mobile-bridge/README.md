# Puente de stickers sonoros hacia WhatsApp móvil / Mobile sound sticker bridge (research)

Estado / Status: experimental, offline only. 2026-11-26.

## Findings / Hallazgos

- [WhatsApp official sticker API issue #1163](https://github.com/WhatsApp/stickers/issues/1163): on 2026-11-24 a contributor confirmed third-party sound sticker API is not available yet, but is on the roadmap. The public Android ContentProvider and iOS pack integration are not an audio import contract.
- [wa-sound-sticker](https://github.com/alkhrzmy/wa-sound-sticker), source inspected: src/sender.js accepts webpBuffer and audioBuffer, dimensions, animated flag, audioSeconds, MIME type and hash. The wire module adds missing protocol fields in memory; no edits to node_modules. This is a runtime hook, NOT a native official integration. No external dependency was installed or executed for this experiment.
- [DavidRamirez206/whatsapp-sound-sticker-bot](https://github.com/DavidRamirez206/whatsapp-sound-sticker-bot): linked-device bot with a different encoding strategy, and a 500 KB visual target. Both projects are unofficial and actual phone compatibility is not established here.
- [Independent protocol notes](https://github.com/7ucg/whatsapp-docs/blob/main/WA_STICKERS.md): embedded audio message; some implementations also use a distinct sound sticker envelope. Compare actual received messages on an explicitly authorized test account before choosing a codec.
- [WhatsApp terms](https://www.whatsapp.com/legal/terms-of-service): unauthorized clients can violate terms and lead to account restrictions. Official device linking does not authorize unofficial clients.

## Recommended experimental architecture / Arquitectura

Phone sends the JSON as a document to a separately owned test account. A private linked-device worker, on a machine controlled by the operator, validates and extracts the two original media buffers; a future reviewed transport returns one sound sticker message to the requesting chat. The user receives it in the real WhatsApp app and can test saving and forwarding. No native editor or video re-encoding. No arbitrary recipient API, no public bot, no account linking in GitHub Pages or current Render importer. Use a secondary test account, restrict inbound chats to explicit allowlist, disable groups, rate limit, reject oversized files before parsing, never log message bodies or session keys, and keep the linked-device credentials separate from repository and public hosting. Real linkage requires explicit operator action; do not request pairing codes via chat. Revoke the linked device after the test.

The existing static site and Render API are unchanged. A private machine or separate persistent worker is required; free stateless hosting is not suitable for durable sessions. Direct Android/iOS native import remains blocked until official API support.

## Offline prototype

`package-adapter.mjs` reads the existing stickers-sonoros/1 envelope and returns the documented buffer arguments for a candidate transport, without any network access or credential handling. It enforces the new combined 2 MB trial, checks RIFF, Ogg/Opus header, dimensions, animation cadence and EXIF SHA-256. It preserves the original buffers. It does not fully decode media, verify Ogg integrity/duration, link an account, send, or prove server acceptance. Add full decode validation before connecting a worker.

Run `node --test experiments/mobile-bridge/package-adapter.test.mjs` from repository root. Fixtures are synthetic container structures, not playable stickers.

## Acceptance gate / Pruebas pendientes

1. Test an actual package generated by the current editor offline; compare SHA-256 before and after adaptation.
2. Review and pin candidate transport and dependencies. Compare envelope variants against known-good test message. Never modify the production client or bypass account protections.
3. Only after explicit authorization, connect a secondary owned account, accept a single document from a consenting test chat and return one sticker. Verify server acknowledgement, reception in the native app, audio playback, re-forwarding, original EXIF and bytes.
4. First test a small 2 s sticker with each component below 500 KB, then progressively test near 1 MB and 2 MB combined, 9 FPS, different resolutions and duration. No size/duration is assumed accepted. Keep native import and linked-device sending as distinct features.
5. Remove the experimental linked device and test data. If successful, design an isolated private deployment; public release requires official compatibility and privacy review.

## Prueba privada de una sola entrega / Single-delivery private trial

On your own computer install Node.js 22+, Git and FFmpeg. Clone the repository, enter `experiments/mobile-bridge`, run `npm install`, `npm test`, `npm start`. The experimental transport is pinned to Baileys 7.0.0-rc14 and candidate source commit 5ffe38b; dependency installation, transitive lock and connection are not verified here. Review dependencies before pairing. Type TEST and enter your own receiving phone number locally (country code and digits, no +). Scan the terminal QR using a secondary WhatsApp account you own; never share QR or credentials. From the allowed phone send the two-second example .sonoro.json as a document to that secondary account. After local structural and audio decode validation, type SEND to authorize exactly one response to the same chat. Rejects groups, unknown senders, old messages and oversized files; no automatic retry. It removes temporary session files best-effort; unlink the experimental device manually afterwards. Relay return is not delivery confirmation. No account connection is performed by CI.

## Prueba web móvil / Mobile web trial

Alternative to the local terminal. Deploy a **separate** Render web service, not the public importer. Use this repository, main, Docker runtime, root directory `experiments/mobile-bridge`, Dockerfile `./Dockerfile.web` and health path `/health`. Configure `BRIDGE_TOKEN` (random at least 32 characters, never commit), `BRIDGE_PAIR_NUMBER` (owned secondary WhatsApp number, international digits), and `BRIDGE_RECIPIENT_NUMBER` (distinct owned receiving number, international digits). Do not paste secrets into chat or GitHub. No service is provisioned by this commit. Free Render may suspend/restart; this one-shot trial uses temporary credentials, not a persistent disk. A persistent production service needs a separate security and hosting decision. Review and test dependencies before real linking.

In the official editor step 4 or mobile package loader open Experimental private send, enter the service HTTPS URL and bridge token, tap Link test account, then Check status until a pairing code is displayed. On the secondary account use WhatsApp Linked devices → Link a device → Link with phone number. Enter the code only in WhatsApp. Return to the web, check status, confirm exactly one send of a 1–3 s package below 500 KB per component. Verify actual reception, sound and forwarding in the native app. Close and manually unlink the experimental device. One send per service instance; no arbitrary recipient, no inbox listener, no automatic retry, no public pairing, no token persisted in the browser. HTTP relay result is not delivery confirmation. The unofficial client can fail to link or trigger account restrictions. No PC is required for the user once the private service is deployed. No deployment, pairing, or real message has been verified.

### .48 — Un único presupuesto de creación / One creation budget

En Crear: 1 MB total recomendado por defecto, 2 MB total opcional experimental. En Enviar no se seleccionan tamaños ni niveles. El puente recibe el paquete original, valida hasta 2.000.000 bytes combinados y decodifica el audio completo sin tope fijo de duración; se mantienen límites de recursos y sesión. En computadora se elige WhatsApp App (predeterminado) o WhatsApp Web (marcador); en móvil solo WhatsApp App. El operador reportó compatibilidad hasta 1 MB sin límite fijo de duración observado; 2 MB y duraciones arbitrarias no son garantía de WhatsApp. La clave privada y el destinatario fijo se mantienen.

In Create: 1 MB combined recommended by default, optional experimental 2 MB. Send does not select size or tier.
